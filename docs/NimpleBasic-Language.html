快速开始

将代码保存为 Hello.nb：

include namespace sys

int Main:
    printfn "Hello, Nimval Basic!" -> System
    return 0
end

运行程序：

nimple-basic Hello.nb

只检查、不执行：

nimple-basic --check Hello.nb
Nimval Basic 会先进行预处理、词法分析、语法分析和整程序静态类型检查。检查失败时，程序不会开始执行，也不会产生输出副作用。

程序结构

方法由返回类型、方法名、可选参数列表、冒号、方法体和 end 组成。普通程序入口为 Main；EasyWindow 程序也可以使用无参数的 void Window。

int Main:
    return 0
end

方法体内的语句按顺序执行。条件块和循环块也使用 end 结束。注释可使用 /* ... */。

void sayHello:
    printfn "Hello" -> System
    return
end

类型与变量

当前解释器使用显式类型声明。常见类型包括：

类型用途示例
int整数int count
float浮点数float ratio
bool布尔值bool ready
string字符串string title
char字符char letter
void无返回值方法void greet:

局部变量使用 var new 声明：

int Main:
    var new count = 3
    var new message = "ready"
    var new enabled = true
    count = count + 1
    return count - 4
end
变量必须在使用前初始化。赋值类型必须匹配；未声明变量、重复声明和作用域错误会在运行前报告。

显式类型转换

使用 as 进行类型转换；as! 表示显式强制转换形式。转换是否允许取决于类型规则，编译期可确定失败的常量转换会被拒绝。

int Main:
    var new count = "42" as int
    return count - 42
end

方法与返回值

参数必须写明类型，格式为 with 参数名 as 类型。

int add with a as int b as int:
    return a + b
end

int Main:
    var new total = add(7, 5)
    return total - 12
end

有返回类型的方法必须在所有可能路径上返回正确类型的值；void 方法使用不带值的 return。

参数和调用检查

  • 调用的参数数量必须正确。
  • 每个实参必须与形参类型兼容。
  • 未声明的方法会在执行前报错。
  • 不允许把 void 方法调用当作普通值使用。

流程控制

条件语句

if score >= 60 then
    printfn "Passed" -> System
else
    printfn "Try again" -> System
end

循环

int Main:
    var new i = 0
    for i < 3:
        printfn "loop" -> System
        i = i + 1
    end
    return 0
end

break 和 continue 只能用于有效的循环上下文。条件表达式需要是布尔值。

表达式与运算符

当前实现支持常用算术、比较、逻辑和一元运算。运算符两侧的类型会静态检查。

类别示例
算术+、-、*、/、%
比较==、!=、<、<=、>、>=
逻辑&&、||、!
字符串拼接"Hello, " + name

具体支持范围以当前解释器实现为准；未实现的语法会明确报错。

控制台与文件输出

内置输入输出语句属于 sys 命名空间，必须使用 sys:: 前缀，或通过源文件中的 const 显式导入。statement "input"、statement "output" 和 statement "iosystem" 分别引入输入、输出和组合语句包；它们不会创建函数。

include namespace sys

int Main:
    print "Hello" -> System
    printf "Score: %d" 100 -> System
    printfn "Done: %s" "yes" -> "logs/run.txt"
    return 0
end
语句行为
print输出文本，不自动换行
printf按格式串输出，不自动换行
printfn按格式串输出并追加换行

输入通过表达式 sys::read 或 sys::read(type) 读取标准输入；可用类型包括 int、float、double、bool、string 和 char。输出目标可为 System，也可为文件名、相对路径或绝对路径。相对路径以当前 .nb 文件所在目录为基准；父目录不存在时会自动创建，文件采用追加写入。

格式占位符

占位符期望参数类型
%sstring
%dint
%ffloat
%cchar
格式串必须是字符串字面量，以便解释器在执行前验证占位符数量和参数类型。缺少输出目标或未使用 sys 前缀/导入对应名称都会报错。三个输入输出标准库文件只引入内置语句，不定义函数包装。

模块与预处理指令

statement

statement "模块名" 用于引进内置标准库模块，必须放在普通代码语句之前；旧关键词 introduce 已移除。标准库文件内部的 statement sys::name 用于声明原生语句定义：

include namespace sys
statement "Math"

标准库模块包括 Math、EasyWindow、input、output 和 iosystem，从解释器可执行文件同级的 Standard library 文件夹读取无扩展名文件。

copy

copy "Math" 会从解释器同级的 Standard library/Math 文件读取并展开源码。显式相对路径或绝对路径会读取对应文件并将内容展开到当前源码中。请只对可信文件使用文件路径形式的 copy。

添加或修改标准库时，直接编辑解释器同级 Standard library 文件夹中的无扩展名文件。发布时必须将整个文件夹与解释器放在一起。

Nimval Basic 0.1.0：作用域与文件类型

作用域解析符 :: 支持模块方法与全局方法访问：

module MathOps:
    int twice with value as int:
        return value * 2
    end
end
int Main:
    return MathOps::twice(::globalValue())
end

.nb 是源文件，.nbf 是首文件，.nbt 是可选尾文件。打开没有 including 方法的首文件时会发出 NB-W2101 并按源码复制方式展开。尾文件采用 key = value 格式，目前会校验但尚不会自动应用到运行时设置。

内置 Math

Math 提供整数辅助方法：

方法签名说明
absIntint absInt with value as int返回整数绝对值
maxIntint maxInt with a as int b as int返回两个整数中的较大值
minIntint minInt with a as int b as int返回两个整数中的较小值
statement "Math"
include namespace sys

int Main:
    printfn "max=%d" maxInt(7, 12) -> System
    return absInt(-5) - 5
end

静态检查

运行前检查覆盖当前已实现语法，包括方法签名、参数类型、返回路径、变量初始化、作用域、运算符、转换、流程控制、格式串和模块可见性等。

建议在运行前把 nimple-basic --check your-file.nb 加入编辑器或构建流程。静态检查不会执行程序，也不会触发文件输出或 GUI。

命令行

命令说明
nimple-basic file.nb检查后运行源码
nimple-basic --check file.nb只做静态检查
nimple-basic --check-stdin file.nb从标准输入读取源码，并以指定文件作为上下文
nimple-basic --version显示版本信息

构建解释器

cmake -S . -B build
cmake --build build --config Release

Windows Visual Studio 用户可以打开 NimpleBasic.sln 构建。解释器使用 C++14。

当前边界与说明

  • 本文档对应 Nimval Basic 0.1.0 的当前实现。
  • class 是已弃用的 module 兼容别名，会产生 NB-W2090 警告；可用 suppress NB-W2090 抑制。
  • module 是静态命名空间，不是可实例化的对象类型；继承、接口/trait、对象生命周期、new/delete 和嵌套类/枚举尚未实现。
  • copy 是源码级展开，部分错误位置显示展开后源码中的行列，未必映射回原包含文件。
  • 所有标准库文件（包括 input、output、iosystem 语句包）都必须随解释器一起分发，并放在可执行文件同级的 Standard library 文件夹中。
